# 古法蓝晒底片整理室

运行：

```bash
npm start        # http://localhost:3040，数据 data/cyanotype-negative-room.json
npm test         # 自动化测试（node:test，零依赖）
```

## 暗房废液中和与转运放行

页面分五段走通：**① 废液建档 → ② 配伍方案 → ③ 处置投药 → ④ 转运放行 → ⑤ 异常恢复**（另有原有“底片工序”页）。

- **建档**：废液桶关联来源药液批次、工序与底片，建档即占桶位（上限12）。
- **检测**：录入酸碱度(pH)、氰化物、重金属、氧化剂、温度、体积；按结果生成配伍处置方案，写明每步**用量（含估算公式）、投加顺序、允许温升与终点**。顺序固定：先冷却→破氰（先调碱再分次投次氯酸钠）→重金属沉淀→氧化剂还原→中和→静置复检。
- **配伍**：按 pH/氰/重金属/氧化剂/温度打标签，酸×含氰、含氰×氧化剂、高温×常温等组合**冲突不混装**；待检测/冻结桶不得参与。
- **投药**：逐步记录实际用量、投后读数与温升；只能按序执行、每步只能成功一次。
- **放行**：终点 pH 6~9、氰<0.5、重金属<0.5、氧化剂<1.0 mg/L、温度≤30°C；**放行人与操作/检测/投药人必须不同**，并**凭承运单据（单号+承运单位）**放行。
- **冻结**：缺项、超温(≥40°C/温升超限)、终点异常、方案过期(24h)、记录改动一律冻结；冻结桶继续占桶位。
- **返工**：冻结后可**另起新批次**，保留父子桶与来源批次关联；新批次须重新检测处置，绝不自动放行。
- **旧数据**：迁移为“待检测(旧)”，检测前禁止处置、配伍与放行。
- **并发与幂等**：投药/放行经单桶串行锁 + 全局写锁（原子落盘）；`Idempotency-Key` 重复提交只成功一次（之后回放原结果），失败不占桶位、不留半批次。

### HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/waste/barrels` | 建档（可带 `Idempotency-Key`） |
| GET | `/api/waste/barrels` | 桶列表（含方案/投药进度、末次读数） |
| POST | `/api/waste/barrels/:id/readings` | 录检测并生成方案 |
| POST | `/api/waste/barrels/:id/doses` | 单步投药（步序、实投量、投后读数） |
| POST | `/api/waste/barrels/:id/release` | 放行人+承运单据放行 |
| POST | `/api/waste/barrels/:id/anomaly` | 异常报告并冻结 |
| POST | `/api/waste/barrels/:id/rework` | 返工另起批次 |
| POST | `/api/waste/compatibility` | `{ids:[...]}` 配伍检查 |
| PATCH/PUT/DELETE | `/api/waste/barrels/:id` | 拒绝并冻结（记录不可变） |

原有 `/api/items`、`/api/items/:id/action`、`/api/stats` 等接口保持不变。
